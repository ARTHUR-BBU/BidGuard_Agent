# Task 9 Constitution Impact

> 状态：引用门禁、受限要求提取和持久化已完成程序化实现；独立复审进行中；尚未向真实模型发送业务文档文本
>
> 范围：单文件招标要求抽取、原文引用校验、要求历史与去重、模型调用台账

## Constitution impact: Yes

Task 9 把“模型只能把原文中可定位的要求交给后续审核”的原则落成了代码边界。它只负责把招标文本拆成可追溯的原子要求，不判断企业是否合规，不替人作投标决策，也不宣称完整招标包覆盖。

## 已落地的硬边界

- 提取 Agent 只有结构化 `RequirementBatch` 输出，没有工具和写权限；服务端通过 `resolve_model_name("extraction", settings)` 选择模型，并受最大轮次、输入 token 和批量上限约束。
- 模型候选必须引用当前项目的当前招标版本；引用页码/章节必须能命中授权 chunk，最小引用原文必须真实存在，否则 fail closed 并记录拒绝码。
- 保存前再次核验招标版本属于当前项目且角色为 `tender`，chunk 不得来自其他版本；跨项目、跨版本和未定位引用不能进入 `requirements` 表。
- 摘录正文必须与授权数据库 chunk 的规范化内容完全一致，文档中的提示注入文字只被当作不可信证据，不会改变提取规则。
- 要求业务指纹与引用位置指纹分开保存；新招标版本只停用旧要求，不删除历史；拒绝事件只记录候选文本哈希，不记录原文正文。
- 每次实际 Runner 调用都必须有数据库会话，并持久化安全的 `LLMCallRecord`，包含范围、版本、chunk、Prompt 哈希、结果和停止原因。
