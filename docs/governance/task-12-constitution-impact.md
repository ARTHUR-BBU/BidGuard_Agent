# Task 12 Constitution Impact

> 状态：持久化进程内审核 Worker 已实现并通过确定性回归；真实业务模型质量仍未验收。
>
> 范围：ReviewJob 持久化、单进程后台执行、中断恢复、审核任务 API 和阶段状态。

## Constitution impact: Yes

Task 12 扩大了 Agent 应用的“持续执行能力”：任务可以在请求结束后继续运行，并在进程重启后恢复。但它没有扩大模型的事实权限、项目范围、证据范围或最终提交权限。Worker 是调度和恢复层，不是新的业务裁判。

## 已落地的硬边界

- `ReviewJob` 是任务事实来源；状态、阶段、错误和尝试次数先持久化再对外返回。
- Worker 原子领取 `queued` 任务，领取条件包含当前状态，避免重复领取同一任务。
- 启动时只把遗留的 `running` 任务回到 `queued`，保留中断原因，不静默删除或伪造完成。
- 文件版本指纹由服务端根据当前项目范围生成；相同活动文件范围的活动任务复用，不允许模型自行指定范围。
- 处理链继续复用解析、ReviewContext、证据工具、引用门禁、Assessment 保存和模型调用台账。
- 阶段只表示真实处理阶段，不计算没有证据来源的完成百分比。
- `partial_failure` 不会被标为 `completed`；已保存的部分结果和可恢复位置继续保留。
- 数据库迁移只增加新字段，不删除或合并旧文件、要求或证据记录。

## 尚未实现且明确禁止冒充完成的内容

- 尚未实现分布式 Worker、租约心跳、并发扩展、优先级队列或自动供应商故障切换；
- 尚未实现人工确认/否决 API、增量复核和完整前端任务工作台；
- 尚未证明真实业务文本的审核准确率、召回率、延迟或成本；
- 任务 `completed` 不是“投标合规”、不是“中标保证”，更不是自动提交或签章授权。
