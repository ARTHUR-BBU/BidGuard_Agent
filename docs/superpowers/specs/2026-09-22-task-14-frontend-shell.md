# Task 14：类型化前端接口与应用工作台规格

## 目的

把 Task 13 已经验证的后端状态和人工确认边界，准确呈现为一个可导航的 BidGuard 前端工作台。Task 14 只建立界面骨架和接口边界，不提前实现项目创建、上传或审核矩阵。

## 用户问题

如果后台只有 API 而没有清晰工作台，用户无法知道从哪里开始、项目在哪里、状态是什么意思；后续页面也会各自解释状态，造成前后端语义漂移。

## 范围

- `DisplayStatus` 与后端五种展示状态一一对应；
- 状态徽标必须同时显示中文文字和视觉样式，不能只依赖颜色；
- `ApiError` 保留 HTTP 状态、机器可读 code 和用户可读 message；
- API 客户端支持 JSON 与 `FormData`，浏览器端不读取或携带供应商密钥；
- 建立 `/projects`、`/projects/new`、`/projects/:id/review`、`/requirements/:id`、`/evidence` 路由；
- 移动端采用顶部导航，桌面端采用克制的侧边栏。

## 明确不在范围内

- 不在前端重新计算风险或合规结论；
- 不伪造项目、审核进度或百分比；
- 不在本任务实现文件上传、项目创建、实时轮询、人工决定提交或报告导出；
- 不把 API key、供应商凭据或整份业务文件写进浏览器代码。

## 验收证据

- Vitest：状态徽标 5/5 通过；
- `npm run lint`：通过；
- `npm run build`：通过；
- 前端壳层仅暴露三项主导航：新建核查、投标项目、企业资料库。
